# 클라우드 구축과 사용자 자원 제공

진행상황 검토·문서 갱신일: 2026-10-07. 아래의 구축·실행 검증일과 구분하며, 실시간 운영 상태를 뜻하지 않습니다.

## 목적과 역할

연구실이 보유한 서버의 컴퓨팅·스토리지 자원을 통합하고, 사용자가 포털에서 필요한 자원을 신청하도록 구성했습니다. 장비 현황 분석, 인프라 설계·구축, 네트워크·스토리지 연결과 사용자 자원 제공 환경 구성을 담당했습니다.

## 1. 보유 장비를 기준으로 역할 배분

CPU·RAM·NIC 속도와 보유 SSD 현황을 검토했습니다. 제어 서비스, 가상머신 실행과 분산 스토리지가 사용할 자원을 고려해 서버별 역할을 배분했습니다. 일부 서버에는 제어·컴퓨트·스토리지 역할이 함께 있으므로 전용 장비만으로 구성된 구조는 아닙니다.

기존 서버실의 1GbE L2 스위치는 외부 이더넷 접속용으로 유지하고, 내부 통신에는 별도 10GbE 스위치를 구성했습니다. Ceph 복제와 VM 스토리지 I/O, 관리 통신이 기존 외부 경로에 집중될 가능성을 고려한 선택입니다. 실제 처리량이 10배 증가했다고 측정한 결과는 아닙니다.

## 2. OpenStack·Ceph 통합

Cephadm으로 NVMe 기반 Ceph를, Kolla-Ansible로 OpenStack을 구축하고 Nova·Cinder·Glance를 Ceph와 연동했습니다. 공유 블록·이미지 저장소와 가상머신 실행 환경을 연결했습니다.

서버별 역할 및 물리 연결은 [하드웨어 구조도](../diagrams/01-hardware.md)에 정리했습니다. HDD 기반 별도 클러스터는 현재 역할을 확정할 근거가 부족해 이 구조도에 포함하지 않았습니다.

## 3. Cinder Volume 신청·제공

2026년 7월 31일까지 Kubernetes 기반 포털과 Cinder Volume 신청·제공 서비스를 구축했습니다. Ceph와 연동한 블록 스토리지를 사용자 요청에 따라 제공하는 단계입니다. 이 시점의 범위를 이후 Kubernetes 클러스터 제공 서비스와 구분합니다.

## 4. Kubernetes 제공 서비스 확장

2026년 8월부터 별도 후속 단계로 진행하고 있습니다. Project·Quota, 클러스터용 이미지, 테넌트 네트워크와 Security Group, 관리 영역과 워크로드 API 간 경로를 구성하고 CAPI/CAPO를 연동했습니다.

2026년 8월 17일 시험용 클러스터의 control plane 1대와 worker 1대가 Ready인 상태, Cinder CSI의 볼륨 생성·사용·삭제 과정을 검증했습니다. 포털 서비스의 통합 구축과 검증은 진행 중입니다.

### 8월 26일 확인한 worker 실행 검증

Provisioner와 Finalizer를 각각 단일 replica로 실행한 검증 기록을 확인했습니다. Finalizer 초기화 과정의 기존 factory 호출을 제거했고, 동일 Pod가 여섯 차례 연속 Ready/Running을 유지하며 재시작 횟수가 늘지 않는지 확인했습니다. Pod에 마운트된 소스와 수정본의 일치, 변경 전후 CAPI 리소스 그래프의 spec이 유지된 점도 확인했습니다. 이 결과는 해당 변경과 단일 replica 실행 범위의 검증입니다.

### 이후 진행한 통합 작업

후속 기록에는 FBS 단일 replica 활성화·상태 조정(reconciliation), Dispatcher 활성화·2 replica 구성 작업, 표준 클러스터 생성 E2E 관련 소스 변경과 다중 replica 준비 상태 진단이 있습니다. 기능별 통합과 문제 해결이 진행됐음을 보여 주지만, 최종 E2E 성공이나 모든 worker의 다중 replica 검증 완료를 입증하지는 않습니다.

10월 7일 검토에서는 위 후속 작업의 최종 실행 성공을 추가로 확인하지 못했습니다. 과거 특정 시점의 replica 수를 현재 배포 상태로 사용하지 않으며, 전체 사용자 서비스는 통합·검증 진행 중으로 기록합니다.

### 다음 검증과 기여 범위

- 포털의 표준 클러스터 생성 요청부터 준비 상태 확인까지 전체 E2E 실행 결과 확보.
- 모든 worker의 역할별 동작과 다중 replica 준비 상태 확인.
- 자원 삭제·회수까지 사용자 서비스 흐름을 연결해 검증.

API/Worker 구현 코드는 AI의 도움을 받았습니다. 본인의 기여는 인프라 통합, 설계 판단, 문제 해결과 검증이며, 이를 독자적인 코드 작성 성과와 구분합니다.
