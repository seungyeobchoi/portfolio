# GPU 장비 기반 AI 챗봇

진행상황 검토·문서 갱신일: 2026-10-07. 아래의 실행 검증일과 구분하며, 실시간 운영 상태를 뜻하지 않습니다.

## 목적과 역할

학사 정보를 제공하는 AI 챗봇 서비스를 구축하고 있습니다. 기존 자원 제공 서비스의 종착점이 아니라 별도의 서비스 목적을 가진 프로젝트입니다.

| 담당 | 범위 |
|---|---|
| 본인 | 챗봇 전체 서비스 구조, 포털 접속·연계 방식, GPU 장비 Kubernetes·네트워크·스토리지, 외부 데이터 인프라 연계 설계 |
| 협업 구성원 1명 | LLM 관련 설계 |

## 독립된 GPU 클러스터

GPU 장비는 Nova compute나 CAPI/CAPO가 생성하는 가상머신으로 편입하지 않았습니다. 기존 관리 Kubernetes의 worker로도 등록하지 않고, 별도 단일 노드 bare-metal Kubernetes로 구성했습니다.

기존 관리 영역에서 GPU Kubernetes API로 연결하는 경로를 검증했습니다. GPU 장비의 기본 클러스터·네트워크·Local PV 검증은 2026년 9월 1일 기록에서 확인했습니다. 등록·배포·모니터링 및 챗봇 요청의 전체 연동 완료를 뜻하지 않습니다.

## 서비스 연결 설계

기존 포털을 사용자 진입점으로 두고, 관리 영역의 챗봇 Gateway를 통해 GPU 클러스터의 챗봇 frontend/backend로 연결하도록 설계했습니다. 모델과 애플리케이션의 실제 서비스 통합은 진행 중입니다.

모델 파일은 Local SSD에 보존해 Pod 재생성이나 이미 저장한 모델로 전환할 때 반복적인 네트워크 전송을 줄이도록 설계했습니다. 처음 받는 모델의 다운로드까지 없애는 것은 아닙니다. AI 서비스 DB는 GPU 장비 밖의 OpenStack에 별도 배치하는 설계이며 배포 완료로 표시하지 않습니다.

## 최신성이 중요한 데이터의 처리

크롤링 결과를 저장하면 다시 크롤링하지 않고 빠르게 조회할 수 있다는 의견을 검토했습니다. 대상이 수시로 변하는 공지사항이라는 점을 함께 논의하고, 최신 정보를 제공하는 목적을 우선해 크롤링 결과를 영구 저장하지 않기로 합의했습니다. 모든 RAG 데이터나 서비스 DB가 불필요하다는 판단은 아닙니다.

## 서비스 설계와 통합 범위

모델 실행, 검색·데이터 저장과 애플리케이션 연결 방안을 검토했습니다. vLLM·Qwen3, pgvector·HNSW, RAG·Rule Engine·MCP는 8월 26일 설계 기록의 후보·구성 검토 항목입니다. 해당 기술의 실제 서빙, 성능·품질 검증 또는 최종 채택을 입증하는 결과로 사용하지 않습니다.

10월 7일 검토에서는 9월 1일 기반 검증 이후의 전체 서비스 실행 성공을 추가로 확인하지 못했습니다. Gateway·모델·애플리케이션 연결과 외부 AI DB는 계속 설계·통합 범위로 기록합니다.

## 확인한 범위와 다음 검증

- 확인한 실행 결과: 9월 1일 기본 Kubernetes, 단일 노드 Pod·Service·DNS 통신, static/dynamic Local PV 기능.
- 다음 검증: 포털에서 Gateway를 거쳐 모델 응답까지 이어지는 요청 경로, 외부 AI DB 연결, 모델·애플리케이션 배포 후 동작 확인.
- 별도 검증 필요: 실제 모델의 응답 품질·처리량·지연. 인프라 연결이나 후보 기술 선정만으로 추론 성능 향상을 주장하지 않습니다.
- 확인되지 않은 범위: 전체 챗봇 운영 완료와 단일 GPU 물리 노드 장애에 대한 고가용성.

실행 결과와 설계·작업 기록의 구분은 [검증 기록](validation.md)을 참고합니다.
