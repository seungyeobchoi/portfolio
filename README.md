# 클라우드 인프라와 스토리지 연구

보유 장비의 제약을 분석해 사설 클라우드를 구축하고, 사용자에게 자원을 제공하는 서비스와 GPU 장비 기반 AI 챗봇 서비스를 설계·구축하고 있습니다. 석사 연구에서는 FDP SSD를 기존 파일시스템 위에서 활용하기 위한 Linux 커널 인터페이스를 구현했습니다.

이 저장소는 취업 포트폴리오용 설계·경험 기록입니다. 운영 소스나 배포용 설정을 제공하는 저장소가 아닙니다. 장비명은 역할 기반 별칭으로 바꾸고 실제 주소, 계정, 인증정보와 원본 운영 로그는 제외했습니다.

## 프로젝트

| 프로젝트 | 기간 | 범위와 상태 |
|---|---|---|
| 사설 클라우드·포털 | 2026.05 ~ 2026.07.31 | OpenStack·Ceph 및 포털 기반 Cinder Volume 신청·제공 구축 |
| Kubernetes 제공 서비스 | 2026.08 ~ 진행 중 | CAPI/CAPO pilot·Cinder CSI 검증, Provisioner·Finalizer 단일 replica 검증 확인; 전체 서비스 통합 진행 중 |
| GPU 장비 기반 AI 챗봇 | 진행 중 | 기본 Kubernetes·네트워크·Local PV 검증 확인; Gateway·모델·앱·외부 DB 설계·통합 진행 중 |
| FDP SSD 커널 인터페이스 | 석사 연구 | MySQL 적용에서 Linux·ext4 인터페이스로 확장, 실제 장치 실험 |

자원 제공 서비스와 AI 챗봇 서비스는 각각의 구축 목적입니다. AI 챗봇에서는 서비스 전체 구조와 인프라 연계를 담당하며, 협업 구성원 1명은 LLM 관련 설계를 담당합니다. 포털 API/Worker 코드는 AI의 도움을 받았으며, 본인의 기여는 인프라 통합, 설계 판단, 문제 해결과 검증을 중심으로 기록합니다.

## 2026-10-07 진행상황 검토

포털은 8월 26일 Provisioner·Finalizer 각각의 단일 replica 실행 검증까지 확인했습니다. 이후 FBS 활성화·상태 조정(reconciliation), Dispatcher 활성화·2 replica 작업, 표준 클러스터 생성 E2E 관련 코드 변경과 다중 replica 준비 상태 진단 기록을 검토했습니다. 전체 생성 E2E와 모든 worker의 다중 replica 검증 완료는 아직 확인하지 못했습니다.

챗봇은 9월 1일 GPU Kubernetes·네트워크·Local PV 검증을 확인했습니다. Gateway, 모델·애플리케이션과 외부 AI DB 연결은 설계·통합 범위이며, 전체 챗봇 운영 완료를 뜻하지 않습니다. 검토일과 실제 검증일, 확인한 결과와 다음 검증 항목은 [검증 기록](docs/validation.md)에 구분했습니다.

## 읽을 때의 기준

- 진행상황 검토·문서 갱신일: 2026-10-07. 실시간 운영 상태가 아닌, 사용자 확인과 보존된 작업·검증 기록을 요약합니다. 문서 편집·정리일을 실행 검증 성공일로 사용하지 않습니다.
- 시험용 클러스터 성공을 전체 사용자 서비스 완료로 표현하지 않습니다.
- Local SSD의 반복 전송 감소는 설계 목적이며, 추론 속도 개선 실측값은 아닙니다.
- FDP의 WAF 개선과 TPM 변화는 구분하고 원인 추론을 측정 사실과 분리합니다.
- 운영용 코드·인벤토리·접속 경로·원본 로그는 포함하지 않습니다.
